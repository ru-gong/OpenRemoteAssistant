# 小米蓝牙遥控器助手 / OpenRemoteAssistant

[中文 / English 快速说明](README.zh-CN.en.md) · [下载 / Releases](https://github.com/ru-gong/OpenRemoteAssistant/releases)

面向**小米蓝牙遥控器 2 Pro** 的 macOS 按键映射与遥控器麦克风接入工具，适合语音输入、语音编程和 **web coding** 等场景。当前实机支持并验证的型号为 RC003-MS（设备自报 RC003）：程序可把遥控器按键映射为 Mac 快捷键，并将遥控器自带麦克风转接成其他软件可选的系统输入。不使用电脑麦克风，不做转写，不保存或上传录音。

**当前是 0.2.9（build 16）开发测试候选，仅支持 RC003-MS。** 已从当前设备核实 `MIOM / RC003 / V2.0 / 2671 / A.7.0.6` 身份、ATVV 服务与特征拓扑，并在不同连接中收到两种 9 字节能力响应：`0b0100000300780000` 与 `0b0100020300780000`。它们均表示 ATVV v1、codec 2、16 kHz、120 字节帧；程序只严格接受这两个完整白名单值。0.2.9 把普通 Fn 映射与语音软件快捷键统一为同一个 macOS 软件 Fn 注入器，并加入 Typeless、豆包输入法、微信输入法及闪电说预设。用户已确认 0.2.8 的 RC003-MS → 遥控器麦克风 → Typeless 基本链路可用；0.2.9 的新增预设、RC003-MS 全部 HID 按键和干净系统安装仍需继续实测。当前开发包使用 ad-hoc 签名，生产签名、公证和干净 Mac 验收尚未完成。

## 使用

1. 完整 `.pkg` 同时安装 `/Applications/遥控器助手.app`、`/Library/PrivilegedHelperTools/OpenRemoteHIDCoreService.app` 和 `/Library/Audio/Plug-Ins/HAL/OpenRemoteAudio.driver`。中间一项是按需运行的“遥控器按键服务”，不是常驻 daemon；放在 root 保护目录是为了避免管理员组可改名 `/Applications` 所产生的提权替换窗口。无需另外下载 BlackHole。安装包不会自行安装；只有使用者打开 `.pkg` 并按 macOS 提示批准后才会写入这些位置。安装不要求重启电脑，也不自动启动应用、按键服务或重载音频服务。完成后退出安装器，打开“应用程序”中的遥控器助手。
2. 应用会检查组件。若显示已安装但尚未生效，可点击“重新加载音频服务…”，阅读全机音频中断提示后确认并批准管理员授权；也可选择稍后处理。成功发出请求后，应用还会等待专用输入和输出端均就绪，才提示组件已生效。随后在系统蓝牙里配对遥控器，只连接一只支持设备，点击“查找已连接的遥控器”并确认绑定。
3. 按键图上点击选键，选常用动作或进行键盘录入。RC003-MS 使用自己的照片与校准目录；0.1.x 的旧遥控器照片保留在原处，不会自动沿用，请按 RC003-MS 实物重新导入并校准。导入不修改原图。按键映射只需批准主程序的输入监控与辅助功能。程序先尝试独占已绑定遥控器；macOS 拒绝时改用共享读取，并只在收到该遥控器按键边沿后短暂屏蔽对应原系统事件，再发送用户设置的目标键。不会读取电脑键盘，也不再启动独立按键服务或请求管理员授权。
4. 使用麦克风时不需要开启按键映射。完整安装后点击“连接遥控器麦克风”，在目标软件选择“遥控器麦克风”，按住右上角语音键说话，松开停止。0.2.5 的公开输入使用 USB-compatible transport 元数据，提高被过滤普通虚拟设备的软件列出的机会；这不代表实体 USB 连接。目标软件仍需自己的麦克风权限，并可能需要完全退出后重开。只跟随系统默认输入的软件，可在助手中明确点击“设为系统默认输入”；助手保存原输入并提供明确的恢复操作。退出时若界面已确认默认仍是遥控器且原输入可用，会让用户选择恢复后退出、保留后退出或取消退出，不会静默切换。

程序不会在安装或连接时自动更改系统默认输入、输出、提示音或其他软件的设备选择。只有用户明确点击“设为系统默认输入”才改默认输入，绝不改扬声器或系统音效；设置与恢复都等待 CoreAudio 属性通知并回读。状态刷新若发现用户或其他软件已经改选输入，会清除旧恢复记录。音频服务恢复时，macOS 或接收软件仍可能重新选择设备。窗口关闭后可继续驻留菜单栏；菜单中可停止全部、退出或打开卸载窗口。

## 语音软件快捷键预设（默认关闭）

普通麦克风接入不需要选择预设。目标软件先选择 **“遥控器麦克风”**，再在助手的“语音软件”菜单中选择对应模式：Typeless 与闪电说“直接说”使用开始、结束各短点一次 Fn；豆包输入法、微信输入法和闪电说“帮我说”则在按住遥控器语音键期间保持 Fn 按下，尾音送完后释放。只需给遥控器助手授予 **辅助功能** 权限；无需开启完整按键映射，也不需要输入监控、管理员授权或 HID 独占。

启用任一预设时，程序对已绑定 RC003-MS 所在 LocationID 的全部匹配 HID 服务执行事务：把遥控器物理语音键报告的键盘 F5 用法映射为 0；任一服务写入失败就回滚，不以部分成功继续。每次真实语音流开始前都会重新核验。点按模式先保留少量开头音频，成功点按 Fn 后才送出缓存；松开时排空已入队尾音（最长 0.75 秒），再点按结束。长按模式在开麦前按下 Fn，送完尾音后释放。切换预设、断连、失败或退出时都会收敛会话并恢复原 F5 映射。

这里发送的是 macOS 事件层的**软件 Fn**：虚拟键码 63，按下时带 `maskSecondaryFn`，释放时去掉该标志；CoreGraphics 会把它规范化为修饰键 `flagsChanged` 事件。它不是实体键盘 Globe 开关，也无法保证被只读原始 HID 的软件接受。普通“映射为 Fn”和所有预设已统一使用同一事件生成路径。Typeless 基本链路已经本机使用确认；其他目标软件仍应按当前软件版本逐一实测。

事务式 F5 中和、软件 Fn 注入和成对点按会话控制直接适配自 [HD838A/remote-mic-app 固定提交 `9e019112fc88534004641499b0b1efc50b491e5e`](https://github.com/HD838A/remote-mic-app/tree/9e019112fc88534004641499b0b1efc50b491e5e) 的 GPL-3.0-only 代码，版权归 2026 SayAll contributors；长按会话和多软件预设由本项目在该边界上新增。本项目未复制其品牌名、bundle 标识、二进制、Logo、App Icon 或商品照片。详细步骤见[验收清单](docs/rc003-ms-acceptance.md)。

## 安装后不重启电脑

“重新加载音频服务…”只在本产品组件已安装但没有就绪时提供。组件缺失时可运行完整安装包；同一产品、结构完整的旧版可直接升级。若固定安装路径的结构或 bundle ID 异常，安装器会拒绝覆盖，请先按它显示的具体错误处理冲突目标。重新加载不能替代安装。已就绪时无需此操作，仅使用按键映射也无需为音频组件重载服务。

**重新加载会短暂中断整台电脑、所有用户的音频，包括其他麦克风、耳机、播放、录音和会议。** 请先结束音频工作；部分接收软件可能需要重新打开或重新选择输入。程序先停止自身映射和语音，用户确认并授权后才向固定的系统 CoreAudio 服务发送一次重载信号，不强退其他应用、不更改默认设备、不重启电脑，也不自动恢复遥控器采音。系统在服务恢复时如何重建其他应用的音频会话，仍需真实环境验证。

取消或选择稍后不影响文件已经安装。请求失败、超时或设备仍未出现时，程序不会自动反复重载或宣称麦克风已可用；保留错误信息，先检查安装并尝试重新打开接收软件。整机重启仅作为故障排查的后备选择，不是新安装包的强制步骤。上游提供仅重启 CoreAudio 的[驱动加载路径](https://github.com/ExistentialAudio/BlackHole#build--install)，本项目将操作限制到固定系统服务，并在应用中增加确认、授权和就绪回读。0.2.5 的实机操作确认旧端点识别规则在主程序与管理员工具之间不一致，导致请求在发信号前被拒绝；0.2.6 已统一为同一份完整指纹规则，修复后的重载仍待本机确认成功。

0.1.3 修复 0.1.2 重载返回失败后整页长期禁用的问题。明确拒绝会结束等待并恢复普通操作；状态未知时可通过“重新检查并恢复操作”只读确认本次后台调用已结束，再恢复普通功能，但不会重复发送不明状态的请求。界面恢复不等于麦克风生效，映射与语音不会自动开启。重载方式改为校验固定系统 CoreAudio 进程身份后向该进程发送一次信号；不再沿用本机返回错误的 `launchctl kill` 调用，不自动回退到其他命令或放宽系统安全设置。详见[音频服务激活与失败恢复](docs/audio-service-reload.md)。

0.1.4 修复按键独占所需的权限层缺失，以及已加载麦克风被错误判定未就绪的问题。按键辅助进程仅在本次映射期间运行，停止后退出；音频改为按插件 bundle ID 及双端点 UID 核验，界面分开显示组件、遥控器连接和收到音频。详见[按键接管与麦克风连接](docs/input-and-microphone.md)。真实授权、按键输出与端到端收音仍须安装后验收。

0.1.5 根据实体测试得到的 `TCC deny IOHIDDeviceOpen / 0xe00002e2` 先消除了随机 root 副本，改用 root 保护固定路径中的同一个 helper app/Mach-O，并把管理员会话失败与普通权限状态分开保存。后续实测确认，其普通权限检查仍作为主程序子进程运行，TCC 归属并未成为独立 helper 身份，因此这一步只修复了执行路径和错误覆盖，不能证明 helper 自身已获输入监控。开发版使用 ad-hoc 签名，升级后可能需要重新批准；公开发行须使用固定 Developer ID 身份、公证和干净电脑验证。

0.2.0 将活动支持范围改为 RC003-MS，并以设备实际返回的 RC003 身份和 ATVV 能力作为启用条件。为避免把旧遥控器的热区套到新硬件上，RC003-MS 的照片与校准改用独立 profile 目录，原文件不删除。能力查询只证明设备声明了相应语音参数，实际按键、按住语音键后的音频包及系统输入仍需安装后验证。

0.2.1 修复 0.2.0 开发包的安装归档缺陷。0.2.0 为清除 AppleDouble 元数据重写 payload 时漏带 `Scripts` 成员，导致安装器在执行前因找不到 `preinstall` 以错误 112 退出；脚本、payload 覆盖和收据写入均未发生，已安装的 0.1.5 保持不变。0.2.1 同时重建并审计 payload 与 Scripts 两个 cpio 归档，拒绝缺失脚本或带 `._*` 元数据的候选。

0.2.2 修复 RC003-MS 能力响应兼容和首次连接状态竞态：严格白名单同时接受 `0b0100000300780000` 与实机返回的 `0b0100020300780000`，仍拒绝截短、扩展或其他字段组合；点击连接时先等待一次新的系统音频设备列表，再判断专用输入和隐藏输出，避免首击读取旧列表。底层 CoreAudio 查询超时时仍保留唯一的 in-flight 标记，直到原调用真实返回，避免定时检查继续堆积。0.2.1 还把普通权限 helper 检查作为主程序子进程启动，实测 TCC 将它归到主程序，导致“按键服务已授权”证据无效。0.2.2 改由 LaunchServices 独立启动固定 helper，并以双向认证套接字传递单次操作；helper 只在认证后生成随机挑战，拒绝启动前预塞、重复和未结束的请求。helper 在开发签名下也启用 hardened runtime，构建与打包会拒绝可放宽动态库注入保护的代码签名权限。它只有在用户侧 helper 权限允许、管理员侧真实独占并返回 `ready` 两个运行阶段都成功时才启用映射。这仍是 ad-hoc 开发包的实体测试候选，不表示已解决公开发行环境的 HID/TCC 问题。

0.2.3 修复实机首次音频流结束时的界面死锁。旧版把 AudioQueue 缓冲回调和 CoreBluetooth 回调都放在主队列，又在主线程同步停止和销毁 AudioQueue，导致销毁等待无法执行的主队列回调，彩球出现后关麦命令也无法继续发送。新版将 AudioQueue 回调放入独立串行队列，旧回调仅异步回主线程并先核对代次和队列身份；停止时先摘除旧队列，再在另一个后台串行队列同步销毁。活动和待销毁队列总数限制为两个，异常销毁时后续连接会失败关闭而不会无限堆积。本机一次性实流探针向专用隐藏输出送入 24 个静音缓冲后，`stop()` 在 0.045 ms 返回且主线程心跳继续。安装包还要求升级前由 Installer 关闭正在运行的主程序，原 preinstall 守卫继续防止竞态。

0.2.4 修复“目标软件只跟随系统默认输入”时的使用缺口。实机上的公开输入已由系统、AVFoundation 和 FFmpeg 枚举，FFmpeg 也能以 48 kHz 打开读取，因此不修改驱动的可见性、声道或默认资格。界面现在显示当前系统默认输入；用户可明确将“遥控器麦克风”设为默认输入。程序只写默认输入属性，写前注册 CoreAudio 属性监听，收到通知并回读目标设备后才显示成功；默认输出和系统输出不变。程序保存原设备 UID，恢复前重新解析并确认设备可用，且只在用户明确操作、当前默认仍是本产品输入时请求恢复。状态刷新发现外部已改选后会清除旧记录。退出不会自动恢复，而是对已确认且可恢复的状态提供恢复、保留或取消三种明确选择。已打开的软件仍可能需要重开音频设置或完全重启，并需自己的麦克风权限。

0.2.5 补上第三方应用枚举兼容层。审阅 [HD838A/remote-mic-app](https://github.com/HD838A/remote-mic-app) 的实现与故障记录后，确认一些目标软件会过滤 transport 为 Virtual 的普通回环设备；仅设置系统默认输入不能绕过这种过滤。OpenRemoteAudio 因此只让用户可见的输入端报告 USB transport 兼容标识，内部隐藏输出仍报告 Virtual，PCM、声道、UID、默认设备资格和应用内精确路由均不改变。该标识不声称存在实体 USB 硬件。驱动与应用会同时核验“公开输入=USB、隐藏输出=Virtual”，避免混装旧驱动时误报就绪。对方项目采用单个双向回环设备；本项目没有照搬其拓扑、名称、标识、二进制或图标。

0.2.5 同时修复正常松键时丢尾音和高频界面刷新。正常 `STREAM_STOP` 不再立即丢弃 AudioQueue 中已经入队的 PCM，而是异步播放至停止，最长等待 0.75 秒后强制回收；错误、断连、退出及新会话抢占仍立即停止，队列总数继续有界。界面电平最多发布 20 次/秒，首帧立即更新。排空只能保护已经到达 Mac 的数据，不能补回遥控器固件尚未发送的缓存。

0.2.6 修复 0.2.5 实机暴露的音频服务激活阻断。磁盘上的新驱动已安装，而 CoreAudio 仍驻留旧版全 Virtual 双端点时，主程序能严格识别为待重载；原管理员工具却只接受“新版已就绪”或“两端均不存在”，把这一精确升级状态误拒绝。新版管理员工具独立复验同一组插件、UID、名称、厂商、可见性、默认资格、通道、在线状态和 transport：当前 USB/Virtual 组合直接判定就绪，精确旧版 Virtual/Virtual 组合允许一次用户授权的重载，两端均未注册也允许重载；任何半残、陌生、身份不符或查询失败的端点继续拒绝。顶部同时标明上次重载操作和当前组件状态，避免把保留的历史错误与最新检查混为一谈。

0.2.7 直接适配固定版本 remote-mic-app 的 Typeless 方案：对绑定遥控器的物理 F5 做事务式中和，每条流开始前复核；开始 Fn 点按成功前保留 pre-roll，正常松开后先排空最长 0.75 秒尾音，再发送结束 Fn 点按。快速连续会话、关闭、断连、失败和退出都有代次隔离与清理；任何中和或开始点按失败均关闭本次音频路径，不回落到未经 Typeless 启动的普通直通。该版本只完成代码与离线验证，实机结果仍以验收清单为准。

0.2.8 修复 0.2.7 的 Typeless 首包失败：开始 Fn 点按期间累积的 pre-roll 会作为一批交给输出，而旧实现错误地要求整批不超过单个 4,096 字节立体声缓冲区。新版先原子核对所需缓冲区数量，再把任意一批单声道 PCM 分块复制到固定有界池；最大五秒 pre-roll 需要 79 个、池中预留 96 个。错误信息现在区分路由变化、空间不足、CoreAudio 入队失败与启动失败。录音和连接不再设置固定时长，仍保留连续两秒无完整音频帧、断连、睡眠、主动停止和退出等故障/生命周期保护。按键映射同时适配参考项目的共享读取与按键屏蔽回退，不再依赖已被本机 TCC 拒绝的独立 helper 授权链。

0.2.9 校正普通 Fn 映射的含义与实现。此前普通映射使用私有事件源和手工 `flagsChanged`，与已经跑通的 Typeless 路径不同；新版统一通过 `hidSystemState` 创建虚拟键码 63 的软件 Fn 按下/释放，并在界面明确它不等于实体 Globe。新增六个语音软件选项：关闭、Typeless 点按、豆包长按、微信输入法长按、闪电说“直接说”点按和“帮我说”长按。长按控制器在开麦前按 Fn，尾音排空后释放，切换、失败和退出时补做平衡释放；旧 Typeless 开关自动迁移为 Typeless 预设。

## 在程序内卸载

先停止映射并确认按键辅助进程结束，再从顶部“遥控器”菜单或菜单栏图标选择 **“卸载遥控器助手…”**。主程序停止功能并退出后，独立卸载窗口继续运行。

- 默认只移除应用、遥控器按键服务及专用音频驱动，保留个人数据。可勾选清理当前用户的按键方案、设备绑定、照片副本、校准信息、主程序偏好设置和保存的原默认输入 UID；不会删除导入前的原照片或其他用户的数据。
- 应用、按键服务和驱动为系统共享组件，移除后本机所有用户都不能继续使用它们。需要用户在 macOS 对话框中批准管理员授权；不保存密码，不安装后台守护，不自动重启。
- 若专用端点仍在使用或被设为系统默认输入，请先结束相关音频会话。若助手已确认当前仍是遥控器默认输入且保存的原输入可用，退出时会让用户明确选择“恢复原输入并退出”或“保留并退出”；其他情况需在系统声音设置中自行确认。卸载器不会强退其他软件或静默改默认音频设置。
- 管理员工具只接受固定卸载操作，不接受任意路径或命令。完成删除并回读本产品的三个固定安装目标和安装收据后，普通权限的窗口才处理可选个人数据及可识别的旧版卸载临时包。
- 取消授权不会删除个人数据；失败或部分完成会明确显示，不能只凭窗口退出判断成功。成功后请保存工作并自行重启，完成系统音频组件移除。

0.1.1 不再创建卸载 `.pkg`，因此不会新增卸载包收据。它清理本产品主收据及可能由 0.1.0 留下的卸载收据。授权执行时只使用临时的 root 私有目录，复制工具并校验固定 SHA-256 后才运行，正常结束及可捕获的错误路径均清理暂存工具。不承诺断电、强杀或磁盘故障后的零残留；安全隔离目录若无法恢复会报告其位置，不自动扩大清理范围。

系统蓝牙配对、权限数据库、安装日志、系统缓存、下载的安装包、旧原型和开发目录不在清理范围。完整清理当前用户数据不是“抹掉系统所有痕迹”。本地开发候选的一次授权方案参考 [Apple DTS 的权限提升说明](https://developer.apple.com/forums/thread/708765)，公开广泛发行前仍须专项审查和真实安装/卸载验收。

## 支持范围与限制

- 开发候选：Apple Silicon / macOS 26。驱动最低构建目标为 macOS 13，但这不扩大应用支持范围。
- 唯一支持的精确样机组合：RC003-MS（设备自报 RC003）/ MIOM / 硬件 V2.0 / 固件 2671 / 软件 A.7.0.6。未知组合拒绝启用，尚未承诺其他型号、Windows、Linux 或 Intel。
- 一次只绑定/连接一只候选。名称不作为身份；蓝牙 UUID、完整 DIS 身份与能力重新核验。HID 与 BLE 没有被证明存在公共硬件标识，因此首次要求用户确认只连接了这一只设备；这不是密码学认证。
- HID 的本机 LocationID 与 RegistryID 共同匹配；重连或重启导致 RegistryID 变化时，需要再次确认绑定，不自动接管另一只。纯音频允许没有 HID 绑定；随后要使用按键，请先授权再重新绑定。
- 已核实 ATVV 服务/特征拓扑，以及同一样机在不同连接中返回的 `0b0100000300780000`、`0b0100020300780000` 两种完整能力响应。程序不放宽解析未知变体。开发候选按已固定的 RC003 上游证据实现 13 键：电源和 TV 也可配置；语音键使用 ATVV 控制边沿并屏蔽重复 HID 边沿。用户已确认遥控器麦克风进入 Typeless 的基本链路可用；当前这只 RC003-MS 的完整逐键报告仍待整理。普通目标键中的 Fn 与语音预设均发送相同的 macOS 软件 Fn 事件，并不模拟实体 Globe；Typeless 以外的软件仍需分别实测。
- 按键映射不再启动独立 helper 或请求管理员授权；主程序先尝试独占，失败后共享读取并短暂屏蔽刚由已绑定遥控器触发的对应系统事件。每个实体键及屏蔽时序仍需安装后确认；共享读取或事件 tap 失败时不能显示映射已启用。
- 断开、睡眠、主动停止、退出或推流中连续两秒没有完整音频帧时停止；不自动恢复上次按住/采音。按住录音和连接会话都不设固定时长。
- 已出现的设备名称、USB-compatible transport、内部电平或离线回环通过，都不能单独证明接收软件实际选中了它并收到真实遥控器声音。

## 配置与隐私

新程序使用用户应用支持目录中的 `OpenRemoteAssistant/`，不覆盖旧 `RC001KeyMapper/`。`mappings.json` 是 schema 5 动作配置，不含个人设备身份；现有合法 schema 4 动作会在内存中兼容读取，并在用户下一次保存时写为 schema 5。`device-binding.json` 使用 schema 2；旧 RC001 绑定只会被识别为已退役，不会迁移到 RC003-MS，也不会阻止重新绑定。界面可显式导入 v1–v5 配置，只迁移动作、不修改来源、不自动启用。RC003-MS 照片和热区校准保存到自己的 profile 子目录；旧通用 `remote-photo/` 保留在原处，不自动迁移或删除。

源码与安装包不含用户照片、录音、屏幕截图或个人配置。照片仅由使用者本地导入。虚拟输入可以被其他有权限的本机软件选择；隐藏输出用于减少界面干扰，并不构成对其他应用的访问隔离。接收软件自己的录音或上传由其设置决定。

## 开发构建

需要兼容 macOS 26 SDK 的 Xcode/命令行工具及 Python 3。源码依赖已按固定版本保存在 `driver/upstream/`，构建不联网、不自动安装任何组件。

```sh
zsh scripts/test.zsh
zsh scripts/build-driver.zsh
zsh scripts/build-app.zsh
python3 scripts/package.py --development
```

最后一条产生一个开发测试安装包和同版本源码归档，放在 `artifacts/`。本地 app/driver 使用 ad-hoc 签名，pkg 未公证，不适合作为无警告的公众发行包；不要以关闭 Gatekeeper 或 SIP 为安装指导。

发行者准备好自己的 Developer ID Application / Installer 身份后，可分别通过 `OPENREMOTE_APPLICATION_IDENTITY` 和 `OPENREMOTE_INSTALLER_IDENTITY` 显式提供，并运行不带 `--development` 的打包命令。这只执行签名，不自动提交公证、上传或安装。公证、附加票据、下载后 Gatekeeper、新机器和实体验收是另外的发布条件。

当前没有把 `SMAppService`、LaunchDaemon 或登录项纳入运行方案。面向他人的开源发行必须先具备稳定的 Developer ID Application / Installer 身份与公证流程，再在干净系统上实测主程序共享读取、逐键屏蔽和权限升级后的身份稳定性；本项目不会把架构图或静态检查写成生产解决。

`scripts/AudioState.swift` 只读系统音频元数据，供安装前保护及本地验收使用；不采音、不改变设备。`apps/macos/Uninstaller/` 包含普通权限的卸载窗口、个人数据清理和固定操作的管理员工具；构建脚本把卸载器内置于主应用，并把按键服务的相同签名副本安装到 root 保护的 `/Library/PrivilegedHelperTools`。自卸载覆盖应用、该按键服务、音频驱动和收据。卸载测试只操作新建的隔离目录及假音频/进程/收据适配器，不调用真实卸载。驱动离线检查实际加载构建出的工厂并验证 PCM 回环，但不把驱动安装进 HAL。
