# 安装后激活专用麦克风

当前 0.2.9（build 16）开发测试候选仅面向 RC003-MS（设备自报 RC003，`MIOM / V2.0 / 2671 / A.7.0.6`）。0.2.9 新增多种语音软件 Fn 预设；音频驱动与服务重载机制没有改变。用户已确认上一候选的 Typeless 基本链路可用，新增预设仍待实测。下文 0.1.x 内容是安装与重载机制的历史，不代表旧遥控器仍在当前支持范围。

0.2.7 延续 0.1.3 开始的安装行为：安装包不会自行安装；只有使用者打开 `.pkg` 并批准后才会写入文件。安装不要求重启电脑，不自动打开应用或重新加载音频。升级时 Installer 会要求退出正在运行的旧版主程序；只关闭窗口不等于退出，底层 preinstall 仍保留进程守卫。完成后退出安装器、打开遥控器助手，由普通权限的应用检查组件。0.2.0 的脚本归档缺失导致安装在执行前失败；该包已作废。

0.2.5 的本机实测发现一处确定性阻断：磁盘已有 USB-compatible 新驱动，CoreAudio 内仍驻留结构完整的旧版 Virtual/Virtual 双端点。主程序把它正确显示为待重载，管理员工具却把两个旧 UID 仍存在当成异常，在发信号前中止。0.2.6 让管理员工具独立执行与主程序相同的完整兼容性检查：当前 USB/Virtual 组合为已就绪；仅精确旧版 Virtual/Virtual 组合或两个产品端点均不存在时允许一次重载；任意半残、陌生、身份、通道、在线状态不符或查询失败仍拒绝。它不信任主程序缓存，也不会仅凭名称或 UID 存在便放宽检查。

0.2.2 还修复首次连接时的系统音频设备列表刷新竞态：用户点击“连接遥控器麦克风”后，应用先等待一次新的专用输入和隐藏输出目录检查完成，再使用该结果决定是否开始遥控器连接。旧缓存、虚拟设备名称出现或刷新任务启动本身都不能作为组件就绪证据。

## 用户看到的流程

1. 组件没有安装：提示运行完整安装包，不把重载当作安装。同一产品、结构完整的旧版可直接升级；若固定路径结构或 bundle ID 异常，安装器会拒绝覆盖，并要求先按具体报错处理冲突目标。
2. 组件已安装、系统尚未注册专用端点：显示“重新加载音频服务…”按钮。仅显示按钮或检测状态不会改变系统。
3. 用户点击后，确认框明确说明操作影响整台电脑的声音、麦克风、录音和会议；默认可选稍后处理。
4. 确认后先停止本应用的映射、语音接收和输出队列，并等待关闭完成，再请求一次 macOS 管理员授权。
5. 固定工具再次核对安装、并发和端点状态。若等待授权期间组件已经就绪，则不发送重载请求。
6. 需要重载时，只对固定的系统 CoreAudio 服务发送一次信号。服务拒绝或结果不明不自动重试。
7. 应用等待专用输入和隐藏输出均匹配产品身份、声道、存活状态，才提示“组件已生效”。不会自动连接遥控器、恢复采音或更改默认设备；用户仍需自己启用，并在目标软件的设备菜单选择输入。只跟随系统默认输入的软件，可在助手中明确点击“设为系统默认输入”。

成功的系统请求不等于驱动已加载，驱动已加载也不等于实体遥控器声音已经通过接收软件验证。就绪等待超时会保留错误提示，不误报收音成功。

## 0.1.3 修复的失败恢复

0.1.2 的实际反馈显示，固定 `launchctl` 调用退出码为 1，系统音频服务没有重启。旧实现没有保留该调用的标准错误，因此不能仅凭退出码判断系统拒绝的具体原因。旧代码又把明确失败一律当成后台仍可能运行，且“重新检查”只更新设备列表，没有解除操作锁，导致界面长期禁用。退出并重新打开应用可恢复旧版界面，但不代表音频已激活。

0.1.3 区分明确拒绝和状态未知。明确拒绝后立即结束等待并恢复普通操作，保留错误原因；不会自动启用映射、麦克风或再次重载。真正的超时、中断或结果不完整仍保留防重复请求保护，但允许点击“重新检查并恢复操作”：只读确认本次调用与相关后台工具确已结束后恢复普通功能。后台仍活跃或检查失败时继续保护；本次状态不明的重载仍不再次发送。界面恢复和音频端点就绪分别显示，不能互相替代。

检查状态不需要管理员权限、不发送信号，也不会关闭其他程序。失败提示显示后仍可查看和选择按键；涉及设备启用、录入和卸载的操作按后台状态保护。

## 权限与副作用

新增工具内置在主应用 `Contents/Helpers/OpenRemoteAudioServiceHelper`，不新增系统安装目录或常驻守护进程。只接受 `--preflight` 和 `--reload`；前者仅检查，后者必须通过管理员授权，不接受任意路径、命令、服务名或信号参数。

普通权限界面使用构建时写入的 SHA-256 核验固定工具，管理员阶段复制到 root 私有临时目录并再次核验后执行。安装与重载工具不修改系统默认设备、不录音、不写入服务配置、不修改系统保护、不自动重启电脑。正常结束会清理自己的暂存工具；不承诺断电或进程被强杀后的零临时残留。

重载固定服务会短暂中断其他软件和其他音频设备的会话。重载流程不修改设备选择，但 macOS 或接收软件在恢复时可能重选设备；必要时重新打开接收软件或重新选择输入。0.2.4 另有独立的“设为系统默认输入”操作，只有用户明确点击并确认后才执行，只改系统默认输入而不改默认输出或系统输出，并保存原输入设备的 UID；它不是音频服务重载的一部分。设置与明确恢复都等待 CoreAudio 属性变化通知并回读结果；状态刷新检查到外部已改选输入时清除旧恢复记录。退出不静默切换默认输入；仅在界面已确认遥控器仍是默认输入且存在有效恢复对象时，才提示用户明确选择恢复、保留或取消退出。重载只能在用户理解并确认后执行，不能把只读检查、安装完成或后台发现未就绪当作授权。

安装、卸载和重载互相检查冲突；不会为了继续而强退其他应用。授权或执行超过期限时显示结果待确认，不重复请求；关闭界面也不能被解释为取消已发出的系统操作。

0.1.3 不再用 `launchctl kill` 发出重载请求。管理员工具只选择系统 `/usr/sbin/coreaudiod`，检查 Apple 系统组件、服务定义、唯一进程、父进程、系统音频账户与启动时间；紧邻发送前再次确认身份一致。0.2.6 对齐已实测参考程序的正常终止语义，只对这一个正 PID 发送一次固定 `SIGTERM`，不用按名称批量终止，也不回退到 `SIGKILL`。系统调用明确拒绝时记录受限的 errno 诊断，不自动切换其他命令，不放宽权限或关闭系统保护。身份二次读取到发送之间仍存在极小的 PID 复用窗口；这一方案不是基于内核代际令牌的原子身份锁定。

目标进程元数据使用 `sysctl(KERN_PROC_PID)` 的完整 `kinfo_proc` 记录，并与完整可执行路径交叉校验；返回长度或字段不符就拒绝，不回退到只看名称的方式。这一底层结构按当前 macOS 26 / arm64 SDK 构建和验证，不保证未来所有 macOS 版本的结构兼容。最初对完整 BSD 进程信息接口的普通权限探针曾被拒绝，该结果保留为诊断证据；不能将普通权限读取失败等同于管理员信号请求失败。

## 验证边界

源码测试使用注入的执行器、合成音频状态和新建的文件夹；不得在普通单元测试中真正终止 CoreAudio。界面预览使用独立模拟执行器，不能请求管理员权限、连接遥控器、打开音频流或重载系统服务。

需要另行在 RC003-MS 真实环境验证：0.2.7 安装后的首次发现、旧端点重载、管理员授权取消与成功、系统服务恢复、公开输入在目标应用内的枚举、首次和再次连接、短句尾音、连续按住/松开不再卡住，以及目标应用收到真实人声。接收软件仍需自己的麦克风权限；在组件生效前已经打开的软件可能需要完全退出并重新启动，才能刷新设备菜单。按照 [RC003-MS 安装后验收清单](rc003-ms-acceptance.md) 记录结果。当前开发候选不承诺所有系统都可免整机重启；重启电脑仍可作为故障排查的最后备选方式。

上游的[构建与安装说明](https://github.com/ExistentialAudio/BlackHole#build--install)提供重启 CoreAudio 的加载路径。Apple 的 [macOS 14.4 发布说明](https://developer.apple.com/documentation/macos-release-notes/macos-14_4-release-notes)说明关键系统进程不再支持 `launchctl kickstart -k`，必要时应使用 `kill`。Apple 的 [kill(2) 文档](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/kill.2.html)说明正 PID 的信号目标及返回值。这里的文档依据不能替代本产品在目标系统的实际重载和音频恢复验收，也不能用于推断旧 `launchctl` 退出码 1 的具体原因。本项目不提供关闭 SIP 的指引。
