# RC003-MS 安装后按键、麦克风与语音软件预设验收清单

适用于遥控器助手 0.2.9（build 16）开发测试候选。当前唯一支持对象是 RC003-MS；它在设备信息中自报 RC003。0.2.9 统一普通 Fn 映射与语音预设的软件 Fn 事件路径，并新增点按和长按两类预设。本清单用于完成真实重载、HID、真实人声、系统端到端输入及各语音软件专项验收。当前安装包使用 ad-hoc 签名，是本机可证伪候选，不代表公开发行方案已经解决。

## 测试前

- [ ] 使用完整的 0.2.9（build 16）安装包；不单独替换 `.app`。升级前按 ⌘Q 完全退出旧版；Installer 应在继续前检查。安装包不会自行安装，只有打开 `.pkg` 并在 macOS 中批准后才写入文件。
- [ ] 在 macOS 蓝牙中只保留这只 RC003-MS 连接，其他同类遥控器暂时断开。
- [ ] 结束会议、录音和重要播放；如需重新加载音频服务，整台 Mac 的声音和麦克风会暂时中断。
- [ ] 准备一个可在设备菜单中选择输入、查看输入电平或回放短录音的本地应用，并允许该应用使用麦克风；另准备一个只跟随系统默认输入的软件或测试路径。
- [ ] 准备要测试的语音软件及不会发送或覆盖重要内容的空白编辑区。记录软件版本、输入设备和快捷键模式；正式测试前把助手的“语音软件”设为“不联动快捷键”。
- [ ] 记录测试前的系统默认输入、默认输出和系统输出的名称与 UID，作为默认设备切换和恢复的比对基线。
- [ ] 记录 macOS 版本、Mac 型号、安装包文件名和测试时间。对外共享日志时删除蓝牙 UUID、设备地址和用户路径。

## 安装与设备身份

- [ ] 安装完成后退出安装器，从“应用程序”打开遥控器助手。安装本身不要求重启 Mac。
- [ ] 程序显示音频组件已安装。若显示尚未生效，结束所有音频工作后只点击一次“重新加载音频服务…”，阅读提示并授权。结果不明时不重复发送，改用界面的重新检查。
- [ ] 若升级前公开输入仍报告 Virtual，0.2.7 保留的管理员工具应把精确旧版双端点识别为待重载并真正发送一次请求；成功后公开输入应变为 USB，隐藏输出仍为 Virtual。任何半残或身份不符的端点仍必须拒绝。
- [ ] 点击“查找已连接的遥控器”。候选详情必须与 `MIOM / RC003 / V2.0 / 2671 / A.7.0.6` 完全一致；只凭“小米蓝牙语音遥控器”名称不算通过。
- [ ] 选中这只设备，确认只连接了它，再绑定。未完全匹配的身份应被拒绝。
- [ ] 连接麦克风时，能力响应只允许完整 9 字节的 `0b0100000300780000` 或 `0b0100020300780000`。两者均表示 ATVV v1、codec 2、16 kHz、120 字节帧；截短、扩展或其他字段组合必须被拒绝。

## 按键映射

- [ ] 在程序中检查“主程序输入监控”和“主程序辅助功能”均已授权；0.2.9 不再显示或启动“按键服务输入监控”，启用映射不应请求管理员密码。
- [ ] 点击“启用映射”。若 macOS 允许独占，界面应显示已独占；若拒绝独占但允许普通读取，应显示“共享读取并屏蔽原按键”，仍然启用。共享读取和事件 tap 任一失败都必须明确停止，不能只显示成功。
- [ ] 先在空白文本或不会导致数据丢失的应用中测试。逐个按下上、下、左、右、确认、返回、主页、菜单、音量＋和音量－，记录程序高亮的按键及目标应用收到的结果。
- [ ] 将一个安全的组合键映射到任意普通键，确认自定义录入、保存和实际触发一致。另把一个遥控器键映射为“Fn（软件按住）”，在明确使用 Fn 的测试应用中验证按住和释放；这只能证明 macOS 事件层的软件 Fn，不应记录成实体 Globe 键。
- [ ] 单独给语音键设置一个无风险目标键，按下和松开一次，确认只触发一次预期动作。这一项同时提供语音键 GATT 实体事件证据。
- [ ] 给电源键和 TV 键分别设置无风险目标键，单独按下并记录程序高亮、键值和目标输出。当前没有它们的实体报告证据；测试失败应作为明确的 RC003-MS 适配问题记录，不得预设通过。
- [ ] 点击“停止映射”。确认状态回到未启用、没有卡住的组合键，遥控器恢复系统原有行为。

## 遥控器麦克风

- [ ] 保持按键映射关闭，确认麦克风功能仍可独立操作。
- [ ] 如果目标应用在安装或音频组件生效前已经打开，先完全退出并重新启动；确认它已获 macOS 麦克风权限。只关闭文档、会议窗口或设置面板不算完全退出。
- [ ] 在本地录音或会议应用的设备菜单中确认能够看到并选择“遥控器麦克风”。0.2.5 的公开输入应报告 USB transport，隐藏输出应继续报告 Virtual；这只是兼容元数据，不代表实体 USB。AVFoundation/FFmpeg 枚举、系统列表名称或 transport 都不能替代目标应用自身的选择与收音证据。
- [ ] 在遥控器助手中第一次点击“连接遥控器麦克风”，确认应用会等待新的系统音频设备列表检查完成再连接，不因旧缓存或刷新未完成而首击失败；等待界面明确显示 RC003-MS 已连接。
- [ ] 按住右上角语音键，对着遥控器连续说话至少 3 秒。确认助手显示已收到音频，同时目标应用的输入电平随语音变化。
- [ ] 松开语音键，确认遥控器停止送音，且未按住时目标输入不继续收到这只遥控器的声音。
- [ ] 连续执行至少 20 次“按住至收到音频，再松开”，确认遥控器助手始终可操作、没有彩球，关麦状态能完成，内存没有持续增长。最终公开发行前把本项扩大到 100 次并保留采样证据。
- [ ] 回放一段很短的本地测试录音，确认开头、结尾和最后一个词都可辨认。正常松键后，已进入 Mac 的 PCM 最长排空 0.75 秒再释放；断连、错误和退出仍立即停止。仅有界面的“已收到音频”或内部 PCM 入队，不足以判定系统端到端通过。
- [ ] 保持遥控器麦克风已连接，在助手中明确点击“设为系统默认输入”并确认。验证系统默认输入变为“遥控器麦克风”，而默认输出和系统输出的 UID 与测试前完全一致；安装、重载和连接本身不应触发这项变化。
- [ ] 在只跟随系统默认输入的软件中验证输入电平或短录音，并确认该软件也已获麦克风权限。能跟随默认输入不替代上一项设备菜单的直接选择测试。
- [ ] 设置请求发出后，确认助手等待 CoreAudio 的默认输入属性变化通知并回读结果；不能只凭写入调用返回就显示成功。当前默认输入仍是“遥控器麦克风”时，明确点击“恢复原输入”，确认恢复到程序保存的原输入 UID；默认输出和系统输出仍不变化。
- [ ] 再次明确设为系统默认输入，然后在系统设置或另一软件中手动改选另一只麦克风。确认下一次状态刷新检查到外部变化后，助手清除旧恢复记录；恢复操作不再使用该旧记录，按 ⌘Q 退出也保持这个更新较晚的用户选择。
- [ ] 再次启动助手并明确设为系统默认输入，不做其他输入切换，随后按 ⌘Q 退出。仅当界面已确认“遥控器麦克风”仍是系统默认输入且存在有效恢复对象时，确认依次出现“恢复原输入并退出”（默认）、“保留并退出”、“取消退出”。分别验证所选结果；若恢复失败，应再出现“返回检查”或“保留当前输入并退出”。在没有有效恢复对象或遥控器已不是默认输入时，应保持当前默认输入直接退出。所有分支的默认输出和系统输出始终不变化。
- [ ] 断开麦克风后再连接一次，确认不需要重启 Mac，也不需要启用按键映射。

## 语音软件快捷键专项

- [ ] 先完成上面的普通麦克风测试，确认“遥控器麦克风”能被直接选择并收到真实人声。快捷键专项不能替代普通音频链路验收。
- [ ] 完全退出并重新打开 Typeless，在 Typeless 自己的输入设备菜单中明确选择 **“遥控器麦克风”**，并确认 Typeless 已获 macOS 麦克风权限。只把该设备设为系统默认输入，不算完成这一步。
- [ ] 保持顶部“按键映射”关闭。只给主程序“遥控器助手”开启辅助功能权限；主程序输入监控、“遥控器按键服务”输入监控和管理员 HID 接管可以保持未授权。确认这种状态下仍能选择语音软件预设；若程序要求完整按键映射权限或管理员密码，本项失败。
- [ ] 绑定唯一 RC003-MS，选择“Typeless · 点按 Fn”，等待界面明确显示 Fn 点按已就绪。启用前后分别记录物理语音键对应 F5 的 `UserKeyMapping`；启用后，绑定 LocationID 上每个匹配服务都应为 F5 → 0，不能只有部分服务被修改。预设默认应关闭，只有用户明确选择时才写入映射。
- [ ] 在 Typeless 的安全空白编辑区按住遥控器右上角语音键并立即开始说一个带清晰首字的短句。确认一次开始 Fn 点按后 Typeless 打开，pre-roll 保住句首，声音来自“遥控器麦克风”，没有额外 F5/Fn 长按或重复开始。
- [ ] 松开语音键，确认已进入 Mac 的尾音先正常排空，最长 0.75 秒后只发送一次结束 Fn 点按；Typeless 停止，最后一个词可辨认，且不会因第二次点按又重新打开。界面内部电平、Fn 日志或生成了部分文字都不能代替首尾完整性检查。
- [ ] 分别测试“很短、在开始点按完成前就松开”的一句，以及持续至少 10 秒的一句。两种情况都应成对结束，Typeless 不留在监听状态，Fn 不留在按下状态。
- [ ] 快速连续说两句：第一句松开后立即再次按住。两句应按顺序各自进入 Typeless，旧会话的排空或延迟任务不能关闭、污染或丢弃新会话；随后重复至少 20 轮并观察是否出现彩球、重复点按或持续增长的内存。
- [ ] 在空闲状态改为“不联动快捷键”再重新选择 Typeless，确认 F5 原映射先恢复再重新中和。随后分别测试改变绑定和退出助手：程序应取消旧任务、恢复保存的 F5 映射，且 Typeless 不被遗留在录音状态。不要在重要文本中执行这些故障测试。
- [ ] 唤醒或重连遥控器后再次发起语音，确认每条流开始前都会复核绑定 LocationID 的全部服务。若制造出缺少服务或写入失败的状态，程序必须在发出 Fn 和声音前关麦、回滚已写服务并保持兼容未就绪；不能以部分中和继续。
- [ ] 若开始 Fn 点按被辅助功能拒绝，确认没有再发送结束点按；若结束点按失败，确认程序明确报错、关闭预设并恢复原映射。修复权限后必须由用户重新选择，不能后台自动发送 Fn。

## 豆包、微信输入法与闪电说预设

- [ ] 在每个目标软件中明确选择“遥控器麦克风”，允许其使用 macOS 麦克风，并把该软件自己的快捷键配置成预设标题所写的 Fn 模式。不要同时打开两个会响应同一 Fn 快捷键的语音软件。
- [ ] 豆包输入法与微信输入法分别选择对应的“按住 Fn”预设。按下遥控器语音键后，目标软件应保持收音；松开后先收到尾音，再看到 Fn 释放并停止。按住至少 10 秒，确认没有被解释成一次短点或留下 Fn 按下状态。
- [ ] 闪电说“直接说”选择点按预设，验证开始与结束各一次 Fn 点按；闪电说“帮我说”选择长按预设，验证整个说话期间 Fn 保持按下。两个功能必须分别在闪电说中设置为 Fn 后再测试。
- [ ] 在按住期间切换预设、断开遥控器或退出程序，确认 Fn 立即平衡释放；在尾音排空期间快速开始下一句，确认旧会话不能释放或结束新会话。
- [ ] 如果某一软件完全不响应，而普通 Fn 映射在其他应用可观察，请记录软件版本和快捷键设置。它可能只监听实体 Globe/原始 HID；不能把这类不兼容报告成遥控器或音频故障。

## 通过标准与故障记录

- **身份通过**：完整 DIS 组合一致，并能绑定唯一 RC003-MS。
- **按键通过**：主程序两项权限有效，启用时进入独占或共享读取模式；所有实体键的原系统事件被对应屏蔽，映射输出逐项一致，停止后正常释放。
- **麦克风通过**：目标应用设备菜单可以直接选择公开输入，只跟随默认输入的软件可通过用户明确操作使用该输入；按住语音键时，真实人声从 RC003-MS 到达目标应用，松开后停止。设置与恢复只改变默认输入；外部改选后旧恢复记录失效，退出不静默切换输入。
- **语音软件预设通过**：目标软件自身明确选择“遥控器麦克风”；不启用完整按键映射时，只依靠主程序辅助功能即可工作；全部匹配服务的 F5 中和、每流复核、点按或长按语义、尾音排空、快速连续会话和关闭/退出恢复均取得实机证据。
- **不可替代的证据**：蓝牙列表名称、能力响应、麦克风出现、USB-compatible transport、内部电平、离线解码或单元测试均不能单独代替上述实体验收。

遇到失败时，保留界面完整错误文本、发生时间、失败步骤、是否已按住语音键、目标应用的输入选择、快捷键模式，以及目标软件当时是开启还是停止。状态不明时不重复授权、不重复重载音频服务，也不通过关闭 SIP、Gatekeeper 或删除其他驱动排查。用户已确认 Typeless 基本链路可用，但新增预设和完整压力项尚未验收；代码和单元测试通过不能勾选实机项目。

当前 0.2.9 不使用 `SMAppService`、常驻 daemon 或管理员按键会话。面向他人的开源发行仍需 Developer ID Application / Installer 签名、公证和干净系统验收，并验证共享读取与屏蔽在支持的 macOS 版本和全部实体键上稳定工作。
